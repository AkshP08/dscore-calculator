## Design Specificity Verdict — AUTHORED FOR THIS PRODUCT (strong)

**LLM assessment:** This is not a category-interchangeable dark dashboard. The mono-data / sans-prose split is load-bearing identity, not decoration — every code number, DV, EG label, and SV is `font-mono tabular-nums`, prose stays sans, so you tell data from sentence at a glance. The signature elements are domain-truthful: the EG color stripe down each row, the A→J difficulty heat badge, DISMOUNT/dropped tags, per-skill CoP page citations, and the connection "+0.0 because…" reasons. ## Overall Impression

This is a confident, product-specific instrument that nails its North Star — precision as personality — and its best feature (the mobile sticky SV bar) genuinely makes the gym-floor scene work. The aesthetic and domain-fit dimensions are near-perfect. **The single biggest opportunity is durability of the working draft:** the app lovingly persists every *saved* routine to localStorage, yet the one piece of state the user is actively building is the only thing with zero durability — and it's thrown away silently by a mis-tap on a header pill. Fix that and the whole control/error-prevention cluster lifts at once.

## What's Working

1. **The mobile sticky SV bar** (`ScoreBreakdown.tsx:164-195`) pins the hero metric above the safe-area inset with a `D·EG·CV` micro-breakdown, uses `role="status"` for screen-reader announcement, and `main` carries matching bottom padding so it never covers the last row. This is the feature that makes the one-handed gym-floor scene real, executed with care.
2. **Diagnostic scoring, not just a number** — dropped elements are visually demoted (opacity-60 + "dropped" tag), EG fulfilment shows *which* skill filled each group, and unawarded connections explain *why* they scored +0.0. This directly serves the product promise "how do I raise it?"
3. **Dual reorder affordance done right** — the desktop drag handle is `[@media(pointer:fine)]`-gated, while up/down buttons expand to 44px on coarse pointers and are keyboard-operable with focus rings. Touch and keyboard users get a real path, not a drag-only dead end.

## Priority Issues

**[P0] Unsaved draft is destroyed silently on navigation**
- **Why it matters:** Tapping another event pill, switching Code of Points, or going Home resets the draft with no dirty-check (`App.tsx:91-95,145-156`; `Header.tsx:49`). This is the most likely and most painful data loss in the app, trivially triggered one-handed. `isDirty` already exists (`App.tsx:167`) but guards nothing.
- **Fix:** Either prompt "Discard unsaved changes?" on any view/event/code change while dirty, or — better — continuously autosave the working draft to localStorage (you already persist routines/customSkills via `useEffect`) so a mis-tap is recoverable and the dirty-guard problem disappears.
- **Suggested command:** `/impeccable harden`

**[P1] Native `confirm()` for delete, and no undo anywhere**
- **Why it matters:** `confirm("Delete this saved routine?")` (`App.tsx:160`) is a jarring OS dialog in an otherwise bespoke console — at the one moment reassurance matters most — and remove-skill has no confirmation or undo at all.
- **Fix:** Replace with an in-system styled confirm matching `SkillDetail`, or lighter-weight, make destructive actions undoable via the toast ("Deleted X — Undo"), which the existing single-toast system can host.
- **Suggested command:** `/impeccable harden` (or `/impeccable delight` for the undo-toast)

**[P1] Modals lack dialog semantics and focus management**
- **Why it matters:** `SkillPicker` and `CustomSkillForm` — the app's two most important task surfaces — have no `role="dialog"`/`aria-modal`, no focus trap, and the picker has no ESC handler (only `SkillDetail` does). Keyboard/SR users tab out behind the overlay and focus never returns to the trigger on close.
- **Fix:** Add `role="dialog" aria-modal="true" aria-label`, a focus trap, ESC-to-close on both, and restore focus to the opener on dismiss.
- **Suggested command:** `/impeccable harden`

**[P2] Difficulty filter row is a cognitive + touch overload**
- **Why it matters:** Up to 11 targets (`all` + A–J) wrap in the picker (`SkillPicker.tsx:105-117`) — the only decision point exceeding ~4 options that isn't inherent to the domain, and they become tiny chips one-handed. The smart search already accepts `E` and `III.41`.
- **Fix:** Collapse DV behind a single "Difficulty ▾" control, or drop it and lean on the query syntax the index already supports.
- **Suggested command:** `/impeccable distill`

**[P2] Dim interactive icons at rest hurt gym-floor glance-legibility**
- **Why it matters:** Reorder arrows, drag handle, and the remove `✕` sit at `text-slate-500` (#64748b) at rest (`RoutineBuilder.tsx:163,182,194,233`). DESIGN reserves slate-500/600 for *disabled/non-essential* — these are active controls at ~3.3:1 on slate-900, barely clearing the 3:1 graphical floor and nearly vanishing in bright gym lighting. It's a violation of the project's own Readable-Text Rule for live affordances. (The deterministic scan has no rule for this, so it is an LLM-only finding.)
- **Fix:** Lift resting state to slate-400 (the informational floor); keep slate-200 on hover/focus.
- **Suggested command:** `/impeccable colorize` (or `/impeccable clarify`)

## Persona Red Flags

**Alex (power user, desk, iterating):** Tapping PH to compare a different event wipes the in-progress FX routine with no warning (P0) — a fast iterator hits this most. No keyboard accelerators — must mouse to "+ Add skill" and Save. No undo on an accidental skill remove forces a re-search.

**Casey (distracted, one-handed, gym floor):** Same P0 draft-loss via fat-fingering a header event pill — the highest-probability trigger on mobile. The connection toggle is 44px tall but only as wide as "+ connect" — a thin horizontal target. DV filter chips wrap to tiny tap targets. The event-card "Build →" hint is `opacity-0 group-hover:opacity-100` — invisible on touch (no hover), so the affordance cue never appears for her.

**Sam (accessibility / keyboard / contrast):** Picker + custom-skill modals have no dialog role, no focus trap, no ESC on the picker (P1). Dim slate-500 functional icons (P2). Several interactive surfaces (SkillCard button, home event/recent buttons) rely on default focus while the reorder buttons have explicit `focus-visible` rings — inconsistent keyboard visibility. Native checkboxes in `CustomSkillForm` render unstyled/low-contrast on the dark panel. The drag-handle `<span>` carries `aria-label="Drag handle"` but isn't focusable or operable — SR noise with no action.

## Minor Observations

- Single-toast model means rapid actions clobber: add-skill then Save shows only the Save toast — the "Added X" confirmation is lost.
- Home has no persistent header; the active code is only visible via the CoP picker's `ACTIVE` tag. Minor, since the picker is right there.
- EG-bonus progress bar hardcodes `maxBonus = 0.5` (`ScoreBreakdown.tsx:61`), so a 0.3 bonus reads as a 60%-full gauge — intentional, but worth a one-line comment lest it look like a bug.
- `SkillDetail` ✕ uses `hover:text-white` while the rest of the system settles to slate-100 — trivial drift.
- The 24 `text-[10px]`/`[11px]` detector flags are all documented-exception false positives (DESIGN.md:257); no action needed.

## Questions to Consider

1. The app faithfully persists *saved* routines on every change, yet the *working draft* — the thing actively being built — is the one piece of state with zero durability. Why isn't the draft autosaved continuously, making the whole dirty-guard problem disappear?
2. The DV filter exposes up to 11 chips, but your search index already parses `III.41` and bare difficulty letters. Does the difficulty filter earn its screen cost and tap-target crowding, or is it a generic faceted-search reflex a fluent user routes around via the query box?
3. Batch-2 flattened the ground and solidified the SV number to honor "emphasis from size/weight, never gradient" — but the hero panel still wears a sky→violet gradient + radial. Is that gradient still *meaning* something, or is it the last decorative holdover the North Star would also flatten?
